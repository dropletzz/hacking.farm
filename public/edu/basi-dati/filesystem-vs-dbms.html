Persistenza dei dati: file system vs DBMS

Modelli di archiviazione, architetture a confronto e criteri di scelta

1 Architettura della persistenza dei dati

L'archiviazione dei dati può avvenire direttamente sul file system oppure delegando la gestione ad un sistema intermedio chiamato DBMS (Database Management System).

Salvataggio diretto su file

L'applicazione interagisce direttamente con il sistema operativo eseguendo operazioni di lettura (read) e scrittura (write) sui file.

Utilizzo di un DBMS

L'applicazione non accede direttamente ai file, ma invia interrogazioni (query) al DBMS. Il DBMS elabora la richiesta, gestisce le operazioni fisiche sul file system e restituisce i dati (risposta) all'applicazione.

2 Confronto tra File System e DBMS

Struttura e tipologia dei dati

File System DBMS
Gestisce i dati come sequenze indifferenziate di byte. Non comprende il contenuto informativo del file, che deve essere interpretato interamente dall'applicazione. Impone una struttura logica sui dati (tabelle, relazioni, documenti JSON, grafi), permettendo di definire uno schema: una struttura che i dati devono rispettare per essere considerati validi.

Integrità e validazione dei dati

File System DBMS
La validazione dei dati è interamente a carico del codice dell'applicazione. Se l'applicazione presenta un bug, è possibile salvare dati corrotti o inconsistenti senza che il sistema operativo intervenga. I vincoli di integrità (chiavi primarie, chiavi esterne, vincoli NOT NULL, CHECK, tipi di dato) sono definiti nello schema ed applicati in modo automatico dal DBMS.

Concorrenza e accessi simultanei

File System DBMS
Offrono meccanismi di blocco (lock) rudimentali a livello di intero file. Se più processi tentano di scrivere simultaneamente sullo stesso file, si verificano race condition o blocchi delle operazioni di I/O che rischiano di rallentare notevolmente l'applicazione. Gestiscono la concorrenza ad alta granularità, anche a livello di singola riga di una tabella. Permettono di risolvere in modo semplice i problemi legati all'accesso simultaneo tramite le transazioni che garantiscono le proprietà ACID (atomicity, consistency, isolation, durability).

Interrogazione e ricerca

File System DBMS
Per cercare un'informazione specifica l'applicazione deve aprire il file ed implementare un algoritmo di ricerca. Il modo più semplice è la ricerca sequenziale che però non è particolarmente efficiente. Forniscono linguaggi di interrogazione dichiarativi (come SQL) che permettono di cercare i dati in modo semplice. Internamente utilizzano strutture dati di indicizzazione (alberi binari di ricerca, hash) che permettono trovare ed accedere ai dati in modo efficiente.

Sicurezza e controllo degli accessi

File System DBMS
Gestisce la sicurezza tramite i permessi del sistema operativo (POSIX/ACL) limitati al livello di file o cartella (lettura, scrittura, esecuzione). Offre un controllo granulare e flessibile degli accessi basato su ruoli ed utenti, che permette di definire permessi specifici su singole tabelle, colonne o righe.

Affidabilità e ripristino

File System DBMS
Un'interruzione di corrente o un crash durante la scrittura su file system può compromettere la struttura del file o causare la perdita parziale dei dati. Utilizza meccanismi specifici che, in caso di incidenti, consentono di riportare il database in uno stato coerente, evitando (o comunque riducendo al minimo) la perdita di dati.

3 Tabella comparativa e linee guida

Caratteristica File System DBMS
Dati gestiti File di grandi dimensioni, dati non strutturati (media, PDF, log). Dati strutturati e relazionali con schemi ben definiti.
Accesso ai dati Lettura/scrittura sequenziale o casuale grezza. Query dichiarative (SQL/NoSQL) con indici.
Concorrenza Lock a livello di file, scarsa scalabilità in scrittura. Lock a livello di riga/pagina, transazioni ACID.
Controllo integrità A carico dell'applicazione. Nativo tramite vincoli di schema.

Nella pratica: architettura ibrida

Nei sistemi moderni si adotta spesso un approccio combinato: il DBMS viene usato per salvare i dati semplici (es. numeri, stringhe, data/ora) e strutturarli in tabelle, il file system é utilizzato prevalentemente per i file binari che possono anche avere grandi dimensioni (immagini, video, allegati). Anche se i file veri e propri sono nel file system, nel DBMS viene comunque salvato l'URL che permette accedere a questi file e scaricarli, insieme ad eventuali informazioni aggiuntive (metadati, collegamenti con altre tabelle, ...).
